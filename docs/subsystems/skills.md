# Agent Skills

> Workspace-local instruction packages that give the agent specialized guidance, declarative tool pipelines, and bundled resources.

## Layout

Skills are discovered recursively beneath `.agents/skills/` in each conversation workspace. A skill is a directory containing `SKILL.md`:

```text
.agents/skills/
├── skill-creator/
│   └── SKILL.md
└── toast-random-number/
  └── SKILL.md
```

Older workspaces may still use `.agents/skills/main/<name>/SKILL.md`; discovery
supports that layout, and CLI migration commands move it to the canonical flat
layout.

`SKILL.md` uses YAML frontmatter. The required fields are `name` and `description`. Optional fields defined by the standard specification are `license`, `compatibility`, `metadata`, `user-invocable`, `disable-model-invocation`, and `argument-hint`. Custom parameters such as `allowed-tools` and `execution` belong inside `metadata`.

Skill names must be 1-64 characters containing lowercase letters, digits, and single hyphens. Descriptions must be 1,024 characters or fewer.

## Discovery and activation

`discoverSkills()` loads skill metadata without loading the full instruction body into the prompt. Discovery scans `.agents/skills/` within the requested conversation group workspace. In browser mode, non-default groups also inherit skills from `DEFAULT_GROUP_ID`; headless mode scans only the requested group. The model receives the names and descriptions of skills that do not set `disable-model-invocation: true`. When a task matches a description, the model calls `activate_skill` with the exact skill name.

Frontmatter parsing is resilient against unquoted scalars containing colons, URLs, or quotes (commonly generated by AI models), and normalizes `metadata.allowed-tools` whether formatted as a space-separated string or a YAML array list.

Activation returns the skill instructions, its directory path, and a sorted list of bundled resource paths loaded from the skill's originating workspace group (`groupId`). Relative paths in the instructions resolve against that skill directory. Scripts must run through the workspace `bash` or `javascript` tools, and repository changes must use the workspace Git tools; skills never receive host filesystem access.

If `activate_skill` is called without a name or targets a skill that failed validation or does not exist, it reports actionable feedback including available skills and matching discovery diagnostics instead of failing silently. Malformed skills and duplicate names are reported as discovery diagnostics. Discovery stops after visiting 2,000 directories. A skill can be refreshed by activating it again, so the returned body and resources reflect the current workspace files.

## Slash Commands & User Invocability

Skills with `user-invocable: true` (or where `user-invocable` is not explicitly set to `false`) can be triggered by users in chat using slash commands matching their skill name (e.g. `/toast-random-number` or `/skill-creator`).

When a slash command is executed:

1. `parseSkillCommand()` matches the message against available skills.
2. If the skill contains a `metadata.execution: { type: "tools", tools: [...] }` block, the orchestrator dispatches `execute-skill-tools` directly to the worker thread. The worker executes the tool chain via `executeToolChain` without scheduling a Task or calling model LLM prompts.
3. If the skill does not contain an explicit `execution` block, the orchestrator enqueues a prompt message `[SKILL COMMAND] Activate the "<name>" skill...` to invoke the standard LLM agent loop.

## Declarative Execution Pipelines & Suppression

Skills can define deterministic sequential tool execution pipelines in frontmatter via `metadata.execution`:

```yaml
---
name: toast-random-number
description: Generate a random integer from 1 to 1000000 and show it in a ShadowClaw toast notification.
user-invocable: true
metadata:
  allowed-tools: javascript show_toast generate_random_number
  execution:
    type: tools
    suppressToast: true
    suppressOutput: true
    tools:
      - name: javascript
        input:
          code: Math.floor(Math.random() * 1000000) + 1
      - name: show_toast
        input:
          title: Random Number
          message:
            $pipe: prev
---
```

### Features:

- **Output Pipelining (`$pipe`)**: Inputs can reference previous tool outputs using `{ "$pipe": "prev" }`, `{ "$pipe": <step_index> }`, or `{ "$pipe": "<tool_name>" }`.
- **Toast & Output Suppression**:
  - `suppressToast: true` suppresses intermediate step toast notifications ("Running skill tool...").
  - `suppressOutput: true` suppresses raw tool step output blocks from rendering into the chat thread.
  - Setting suppression flags at the top-level `execution` block automatically cascades down to all steps in the tool chain unless explicitly overridden per step.

## Default Bundled Skills

ShadowClaw includes standard default skills under `.agents/skills/`:

- **`skill-creator`**: Guide for creating, editing, reviewing, and validating declarative skills and supporting resources. (Example skills such as **`toast-random-number`** are included in the `shadow-claw-template` repository).

## Agent Skills Discovery Index (RFC v0.2.0)

ShadowClaw implements the **Agent Skills Discovery RFC (v0.2.0)** (`https://schemas.agentskills.io/discovery/0.2.0/schema.json`), generating a standardized machine-readable discovery index at `/.well-known/agent-skills/index.json`.

### Features:

- **Manifest Parsing:** Parses YAML frontmatter across `.agents/skills/**/SKILL.md` to extract skill names, descriptions, compatibility, and execution tool/script configurations.
- **Dependency Tracking:** Links skills to their referenced declarative tools (`.agents/tools/*.json`) and companion scripts (`.agents/scripts/*`).
- **Cryptographic Verification:** Calculates SHA-256 digests (`sha256:<hex>`) for all indexed skills, tools, and scripts to enable tamper detection and caching.
- **RFC 3986 Relative URLs:** Emits standardized relative URLs (e.g. `../../.agents/skills/...`) relative to the `.well-known/agent-skills/index.json` location.

### CLI Generator:

The index can be generated or refreshed on demand via the CLI:

```bash
npx shadow-claw skills:index [dir]
```

Options include `--out-dir <dir>`, `--out-file <file>`, `--stdout`, and `--no-write`.

### Build Pipeline Integration:

During `shadow-claw build` (`bin/build.mjs`), the build runner automatically invokes `generateSkillsIndex(contentRoot)` when `.agents/skills` is present. It writes the index to `<contentRoot>/.well-known/agent-skills/index.json`, copies `.agents/scripts` into `dist/public/.agents/scripts`, and publishes `.well-known` directly into `dist/public/.well-known`.

## Static publishing

For content-only sites, skills under `.agents/skills/` (and legacy `.agents/skills/main/`) are copied into the build manifest and seeded into the group workspace. A skills purge marker can clear previously seeded skills directories before the current published skills are seeded; see the template README for the marker format.

## Remote Skill Discovery and Importing

Skills can be discovered and imported across compatible templates and peer sites adhering to the Agent Skills Discovery RFC v0.2.0 specification:

- **Browser UI**: Accessible via the "Import" modal in `<shadow-claw-tools>` (`/settings/tool-configuration`), providing quick-pick presets (pwgen Knowledge Hub, Block Garden Knowledge Hub, Weather Agent) or custom site URLs.
- **Headless CLI**: Discover and import skills directly into an agent workspace via:

  ```bash
  # Import all skills, tools, and scripts from an RFC v0.2.0 discovery manifest
  npx shadow-claw agent import https://xt-ml.github.io/shadow-claw-agent-cli-weather/

  # Import from GitHub shorthand, GitHub repo/tree URL, or local directory
  npx shadow-claw agent import vercel-labs/agent-skills@web-design-guidelines
  npx shadow-claw agent import ./my-local-skills

  # Selectively import specific skills
  npx shadow-claw agent import https://example.com/ --skills "my-skill"
  ```

- **Verification & Storage**: Artifacts are validated against SHA-256 digests and saved into canonical flat layout `.agents/skills/<name>/SKILL.md` (or legacy `.agents/skills/main/<name>/SKILL.md`) along with any companion `files` (`scripts/`, `references/`, `assets/`) in the workspace directory.

## Open Agent Skills (`npx skills`) & `skills.sh` Ecosystem Integration

ShadowClaw is 100% compatible with the [Open Agent Skills](https://agentskills.io) ecosystem, the [skills.sh](https://skills.sh) registry, and the [`npx skills`](https://github.com/vercel-labs/skills) CLI.

Developers and autonomous agents can discover, install, and run skills published to [skills.sh](https://skills.sh) directly within any ShadowClaw workspace.

### Finding and Installing Skills from `skills.sh`

The `shadow-claw skills find <query>` command queries the [skills.sh](https://skills.sh) directory API (`https://skills.sh/api/search`) to search thousands of community and vendor skills (e.g. Vercel, Matt Pocock, Anthropic), with graceful fallback to native searching:

```bash
# Search for skills across the skills.sh directory
npx shadow-claw skills find "react"

# Install skills directly from skills.sh / GitHub repositories into .agents/skills/
npx shadow-claw skills add vercel-labs/agent-skills
npx shadow-claw skills add https://github.com/mattpocock/skills --skill grilling

# Regenerate and synchronize the Agent Skills Discovery index
npx shadow-claw skills:index
```

### Canonical Flat Directory Layout & Template Migration

ShadowClaw standardizes on the **Canonical Flat Layout**:

- **Skills**: `.agents/skills/<skill-name>/SKILL.md` (and optional companion files in `scripts/`, `references/`, `assets/`)
- **Tools**: `.agents/tools/<tool-name>.json`
- **Scripts**: `.agents/scripts/<script-name>.js`

This layout aligns directly with the universal agent ecosystem (`npx skills`, Claude, OpenAI Codex, GitHub Copilot) without requiring runtime syncing or parallel copies.

#### Automatic Migration for Existing Templates

When using CLI commands (`shadow-claw build`, `shadow-claw agent skills`, `shadow-claw skills:index`, `shadow-claw agent init`), existing templates or workspaces with legacy `main/` folders (`.agents/skills/main/<name>`, `.agents/tools/main/<name>.json`, `.agents/scripts/main/<name>.js`) are automatically migrated into the canonical flat layout, and empty `main/` folders are cleaned up.

#### Backward Compatibility

For unmigrated workspaces or remote sites, ShadowClaw continues to discover skills and declarative tools from both flat and legacy `main/` paths, prioritizing canonical flat definitions when deduplicating.

### Using `npx skills` Directly or via `shadow-claw`

You can run `npx skills` directly in any ShadowClaw workspace or use the built-in `shadow-claw skills` / `shadow-claw agent skills` commands. Because skills in the universal agent ecosystem belong to the workspace directory (`.agents/skills/`), `shadow-claw skills` is workspace-scoped and does not take or require a conversation `--group` flag:

```bash
# Install skills directly with npx skills from skills.sh or GitHub
npx skills add vercel-labs/agent-skills --skill web-design-guidelines -a universal -y

# Or manage skills through the top-level ShadowClaw CLI (workspace-scoped)
npx shadow-claw skills add vercel-labs/agent-skills@web-design-guidelines
npx shadow-claw skills list
npx shadow-claw skills find react
npx shadow-claw skills init my-custom-skill
npx shadow-claw skills sync
npx shadow-claw skills remove my-custom-skill
npx shadow-claw skills restore

# Regenerate the RFC v0.2.0 discovery index after modifying skills:
npx shadow-claw skills:index

# Also available under agent subcommand:
npx shadow-claw agent skills list
```

### Graceful Degradation & Keep vs. Delegate Boundaries

- **Kept Internally by ShadowClaw**:
  - **Browser Web Worker & OPFS Runtime** (`discoverSkills`, `loadSkill`, `parseSkill`, `executeActivateSkill`, `executeSkillToolChain`): Runs natively in the browser and in Node.js without requiring child processes.
  - **RFC v0.2.0 Discovery Manifests with Declarative Tools & Scripts** (`fetchDiscoveryManifest`, `importRemoteArtifacts`, `generateSkillsIndex`): Imports and auto-enables ShadowClaw's declarative `tools` (`.agents/tools/*.json`) and portable ESM `scripts` (`.agents/scripts/*.js`), and emits companion `files: ["SKILL.md", ...]` arrays in `.well-known/agent-skills/index.json` so external `npx skills` clients download all companion resources.
- **Delegated to `npx skills` with Automatic Fallback**:
  - When adding/managing ecosystem packages in the CLI (`shadow-claw agent skills add|remove|find|update|restore` or `shadow-claw agent import <owner/repo>`), ShadowClaw delegates to `npx --yes skills` (`-a universal`) and reads `<workspace>/skills-lock.json`.
  - If `npx` is unavailable, offline, or running in the browser UI (`<shadow-claw-tools>`), ShadowClaw degrades transparently to its built-in HTTP/GitHub/local filesystem resolver (`fetchDiscoveryManifest` + `importRemoteArtifacts` + `importLocalSkillsDirectory`).
